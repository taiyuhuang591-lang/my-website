ARKAI ｜ 照護方舟

📌 專案目標與應用情境

以醫療隱私保護為核心設計概念，旨在輔助護理人員進行照護記錄之結構化分析。由於病歷含有患者姓名、身分證字號與病況等高度機敏個資，不可直接發送到外部公有雲；系統核心是在醫療院所本地端先完成敏感資料去識別化遮罩，再送往雲端 AI 進行輔助分析。

👤 個人實際負責工作 (團隊協同開發，專責以下模組)

🛡️
本地端機敏資訊去識別化： 設計並實作本地端資料去識別化遮罩邏輯，確保病患個資在離開院所內網前已完成關鍵特徵替換與脫敏。
🔍
資料送出前檢核機制： 實作多層資料檢核規則，驗證去識別化完整度，防止未處理的機敏欄位意外流出。
⚡
FastAPI 後端與 AI 服務鏈串接： 參與後端 API 開發與護理紀錄 AI 分析流程介接，設計健全的資料交換格式與異常重試流程。
🐳
Docker Compose 多容器部署與排查： 配置 FastAPI、PostgreSQL 與 AI 處理服務的多容器環境，排查網路通訊、環境變數與啟動依賴順序。

🔧 使用技術

Python FastAPI Docker Docker Compose PostgreSQL Cloud AI API 去識別化實作 (Regex)

⚠️ 遇到的問題與處理方式

問題 1 Docker Compose 啟動時 FastAPI 服務過早連線資料庫導致連線失敗
處理方式 調整 Docker Compose 啟動相依設定，於 PostgreSQL 服務加入 healthcheck 健康檢查條件，並在 FastAPI 啟動腳本中實作資料庫連線重試等待（Retry Loop），確保資料庫真正就緒後才開始接受請求。
問題 2 非結構化照護文字去識別化時容易遺漏特徵或誤傷醫療專用術語
處理方式 建立多階段模式匹配與語法結構檢核規則，針對病患姓名、身分證號、日期與特定代碼進行獨立遮罩比對，並在送出前實施抽樣校驗，兼顧隱私防護與後續 AI 分析之語意完整性。

🛡️ 問題、處理方式與驗證結果 (真實參與情境)

案例 1 敏感設定檔暴露與容器端點未授權存取

處理方式 於 Nginx 反向代理配置中加入規則封閉 `.env` 及敏感隱藏路徑，收斂容器 Port Mapping 僅綁定 localhost，並調整檔案權限至最小必要權限 (chmod 600)。

驗證結果 透過外部網路工具進行路徑探測與掃描，確認該路徑均回傳 403 Forbidden 或 404 Not Found，外部無法直接讀取設定內容。

案例 2 密集字典爆破探測與異常請求流量

處理方式 即時分析 access.log 篩選高頻錯誤登入特徵，撰寫 UFW / iptables 規則直接封鎖攻擊來源 IP，並在反向代理加入速率限制（Rate Limiting）。

驗證結果 封鎖後攻擊來源 IP 連線立即被 Drop，日誌中的異常錯誤請求迅速降為零，系統負載恢復穩定。

案例 3 資料庫勒索與竄改風險之災難復原準備

處理方式 撰寫定時自動化備份腳本，將資料庫導出並存放於具獨立權限的備份目錄，落實唯讀屬性隔離。

驗證結果 在全新 VM 測試實例中執行還原腳本，確認資料庫結構與測試資料均能 100% 成功還原無缺漏。
